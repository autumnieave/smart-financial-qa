## 四、正式指标基线（新口径）

| 指标 | 值 |
| --- | --- |
| 题数 | 30（跳过 0） |
| **Hit Rate@10** | **0.3472** |
| **Precision@10** | **0.1192** |
| **MRR** | **0.3381** |
| 零相关题 | 14 |
| Hit Rate@20 / Precision@20 | 与 @10 相同（标注集只覆盖 top-10，K=20 无新增片段） |
| 计入 Precision 的片段 | 275 / 300（25 条按判据 3 排除） |

**计算口径（可审计，与 JSON `口径` 字段一致）**

```
Hit Rate@K  = Σ题[ top-K 内 (完全相关×1.0 + 部分相关×0.5) / 该题 (完全相关+部分相关) 总数 ] / 30
Precision@K = Σ题[ top-K 内计入片段中 (完全相关×1.0 + 部分相关×0.5) / top-K 内计入片段数 ] / 30
MRR         = Σ题[ 1 / 首个(完全相关或部分相关)片段排名 ] / 30
```

> **口径说明**：本指标的 Hit Rate@10 分母为标注集内相关数，不等价于标准 Recall@K（需全语料 ground truth）。

## 五、指标口径变更声明（重要）

**本报告使用新口径：四态判定 + 部分相关 0.5 + Precision 只数「计入」条数。**

| 口径 | Hit Rate@10 | Precision@10 | MRR | 说明 |
| --- | --- | --- | --- | --- |
| B-24A 草稿（二值模型判定） | 0.7000 | 0.2167 | 0.4037 | 已被本报告取代 |
| **B-24B 终稿（本报告）** | **0.3472** | **0.1192** | **0.3381** | 四态人工判定 |

**两者不可直接对比，原因有两层：**

1. **标注来源不同**——草稿是模型预标注（且只看到片段前 400 字），终稿是人工看全文的判定；
2. **指标定义不同**——新口径给部分相关 0.5 权重、Precision 排除同文件第 3 条起。

**尤其要注意：旧口径的 Hit Rate@10 是退化指标。** `eval/retrieval_metrics.py:86,94` 把 `total_relevant` 取成 top-10 内的相关条数，而分子也是 top-10 内的相关条数 → **有相关即为 1.0**。所以 `0.7000` 的真实含义只是「30 题里 21 题在 top-10 至少有一条相关」（二值命中率），不是召回率。

**因此明确禁止**：在简历、面试材料、对外口径中使用「0.7000 → 0.3472」这类对比，也不引用 L5 的任何具体数值（按 L5 的报不报纪律，该层只报「已完成、口径与基线已归档」）。

## 六、调参建议

### 6.1 语料 / 分块侧问题（与检索参数无关，单列）

- **事实**：300 条片段里 **135 条全文 ≤ 400 字**，其中 **24 条 ≤ 50 字**，最短只有 **1 个字**（B2073 rank8 = 「状」；另有「成长能力」4 字、「和生物药学专家」7 字）。
- **问题**：这些碎片块被写进了索引，并且排进了 top-10。
- **建议**：入库分块侧加**最小长度过滤**或与相邻块合并（例如 < 100 字不单独成块）。
- **理由**：碎块既占 top-10 名额直接压低 Precision，也可能挤掉真正有数值的块——属于「调 top-K / RRF k / rerank 数都救不了」的一类。

### 6.2 检索侧

1. **主体与期间没有进入检索约束**——备注里 **16 条**提到缺公司名/主体、**13 条**提到期间不符（非 2025Q3，两类有重叠）。建议在检索侧显式注入主体与期间（BM25 查询词加权，或对 payload 的 `stockName` / `publishDate` 加过滤），而不是只靠生成侧纠偏。
2. **召回层同文件扎堆**——同文件重复情况：出现 1 次 203 组、2 次 24 组、3 次 7 组、4 次 3 组、6 次 1 组、**10 次 1 组**（最坏一题 top-10 全部来自同一文件）。线上主链路有 `RERANK_MAX_PER_FILE=2`（`config/rag_config.py:136`）兜住，但**本层测的是召回层（未经精排）**，所以评测口径必须与线上对齐，否则「召回层指标」与「线上上下文」不是同一件事。
3. **排序本身不是主要瓶颈**——有相关片段的题里，8/16 的首个相关片段就在 rank 1。瓶颈在「top-10 里根本没有完全相关片段」的 14 题。

### 6.3 待验证项（**不在本轮结论内**）

本层只覆盖 top-10，**无法判断「加深 K 是否有用」**。下一步可做的对照：取 `RETRIEVAL_K=50` 的召回候选，检查其中是否已包含后来被判完全相关的片段——

- 若 **K=50 里有、top-10 里没有** → 问题在精排 / 收敛策略（`RERANK_TOP_N`、`RERANK_OVERSAMPLE`、每文件上限）；
- 若 **K=50 里也没有** → 问题在语料 / 分块侧，调检索参数无用。

## 七、边界与未做项

- 标注集只覆盖检索 **top-10**，不是语料全集 → **Hit Rate@K 不等于标准 Recall@K**（标准 Recall 需全语料 ground truth），分母口径以此为前提。
- 本层测的是**召回层**（`HybridRetriever.retrieve(top_k=10)` 直接输出），**不是线上主链路**（`RETRIEVAL_K=50` → qwen3-rerank → `RERANK_TOP_N=10`，oversample×2，每文件 ≤2）。
- 仅 30 题 / 300 片段 → **不做统计显著性声称**。
- **L5 仍按纪律不外报**：已有正式基线，但不把具体数值写进简历 / 面试材料。
- 判据 3 按 **rank 序次**实现（同文件第 3 条起排除，共 25 条）；若改为「第 3 条**相关的**起排除」，需重算该列并重出基线。
- 未做：双人独立复核（本轮为单人判定）；K=50 对照（见 6.3）。
