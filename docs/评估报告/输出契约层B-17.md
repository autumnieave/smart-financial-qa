# 输出契约层 B-17（2026-09-09）

> 结论：四类模型输出（supervisor 拆解 / aggregator 汇总 / metric 标准化 / SQL 产物）已由 `utils/output_contracts.py` 契约模块统一校验并记录格式错误事件；真实指标标准化 10 题冒烟**格式错误率 0/10**，非法输出不再透传下游。pytest 全量 **223 passed**（189 + 34 新增）。

## 1. 目标与口径

- 对齐设计方案 §3.5.5（输出格式约束）与 §6.7.1（结构一致性度量）：校验失败 = 格式错误事件，调用侧拒绝透传并走既有重试/兜底；事件落盘 `训练结果数据/output_contract_stats.jsonl`，可按 kind 汇总格式错误率。
- 纯逻辑模块、零外部依赖：不调 LLM/MySQL/Qdrant，34 例单测全部离线。

## 2. 落地内容

| 产物 | 契约校验 | 接入点 | 失败处理 |
| --- | --- | --- | --- |
| supervisor 拆解 | `validate_supervisor_output`（agent 白名单 + 非空 query；无任务需 direct_answer） | `agents/langgraph_multi_agent.py::_parse_tasks` | 记录 supervisor_tasks 事件；坏任务不透传（空任务原有路由已走 finalize 兜底） |
| aggregator 汇总 | `validate_aggregate_result`（对象 + 非空 content；image/references/chart_json 类型） | `_aggregate`（merge 后） | 记录 aggregate_result 事件；缺 content 拒绝透传，替换兜底文案 |
| metric 标准化 | `validate_metric_plan`（standard_fields / time_grain.mode / calculation.kind / filter_terms） | `tools/native_financial.py::_standardize_metrics` | 记录 metric_plan 事件；非法回退旧自选路径（原有行为） |
| SQL 产物 | `validate_sql_output`（仅 SELECT/WITH、危险关键字、全角标点、语句数/长度上限） | `_generate_sql`（三层防线前） | 记录 sql_output 事件；非法带错误文案进入既有重试 |

## 4. 说明与局限

- 真实冒烟仅覆盖 metric_plan（指标标准化小 JSON，成本低）；supervisor / aggregator / SQL 三类事件的真实统计随 Agent 调用自动累计（事件 jsonl 已接通），本轮以 34 例单测离线覆盖其判定逻辑。
- 事件口径：metric_plan 按「标准化 LLM 调用」计数；sql_output 按「生成尝试」计数（重试会多次计数）；aggregate_result 按汇总节点计数——报告格式错误率时需注明计数粒度。
- 兜底话术模板（refuse/suggest/human 三层，prompts/fallback.py）属 B-18，依赖 B-17 的契约语义，未在本轮落地。
- 后续演进：函数式校验 → JSON Schema / Pydantic 模型化；格式错误率接入 eval 一致性套件（B-22 计划）。
