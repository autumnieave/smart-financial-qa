# 数据管道契约：分层口径与下游合格线（v1）

> 版本：契约 v1（2026-10-17）
> 适用范围：`research_reports_v3_structured` 及后续按本契约重建的集合（建议 `research_reports_v4_contract`）
> 一句话：把“覆盖率”从全库一个数拆成 `doc_type × table_type × table_scope`；`unit` 按 `cell → caption → footnote` 回退，多单位置 `None`，不猜；表级与 chunk 级不可互除。

## 一、结论先行

1. **表级全库**：3,148 张表，`unit` 可提取 **803 张（25.5%）**，零候选 **2,047 张（65.0%）**，多单位 **298 张（9.5%）**。
2. **`unit` 适用域**：`financial_statement / valuation / forecast / industry_summary` 共 **1,963 张**，`unit` 覆盖 **618 张（31.5%）**，零候选 **1,072 张（54.6%）**。`ranking / pipeline / other` 不进入核心 `unit` 分母。
3. **个股财务报表**（`stock|financial_statement|stock`）：377 张表，`unit` **51.2%**；表内报告期 **43.8%**，但 chunk 级检索字段的报告期是 **81.2%**——两者口径不同，不能直接对比。
4. **行业汇总表**（`industry|industry_summary|industry`）：611 张表，`unit` 仅 **5.2%**，`publish_year` **98.7%**。这类表的主要期间键是发布年，不是报告期，也不是货币单位。
5. **旧口径 878 → 新口径 803 不是退化**：75 张表在旧口径下按“第一个来源”取了单一单位，新口径发现同表还有另一种货币单位，按“不猜”置为 `multi`。`223 + 75 = 298` 张多单位表，数字闭合。

## 二、字段与取值定义

### 2.1 `doc_type`

| 值 | 定义 | 用途 |
|:--|:--|:--|
| `stock` | 个股研报（围绕一家上市公司） | 报告期、股票代码的主要适用域 |
| `industry` | 行业 / 策略 / 周报（市场或行业层面） | 期间键优先用 `publish_year`；`report_period` 只在明确提及时使用 |
| `other` | 无法归入以上两类 | 不进入核心分母；单独报告 |

本语料 473 篇文档都有 `doc_type`，因此表级 `table_scope=unknown` 实测为 0；这不代表表级证据充分，只代表文档级先验可用。

### 2.2 `table_type`（7 类，规则 v1）

| 值 | 定义 | `unit` 是否进入核心分母 | 备注 |
|:--|:--|:--:|:--|
| `financial_statement` | 资产负债表 / 利润表 / 现金流量表 / 主要财务指标 | ✅ | 单位最常见，也最容易同表混用（营收百万元、EPS 元） |
| `valuation` | 估值、市值、PE/PB、股价、基本数据卡片 | ✅ | 价格用元、市值用百万元/亿元，天然多单位 |
| `forecast` | 盈利预测 / 预测指标表 | ✅ | 必须区分实际期（A）与预测期（E），不能把预测期当报告期 |
| `industry_summary` | 行业汇总、策略、行业数据表 | ✅ | `publish_year` 是主期间键；`report_period` 不一定适用 |
| `ranking` | 排名、涨跌幅、公司列表 | ❌ | 主语义是排序/比较，不是货币计量；其中的市值列可单独报告 |
| `pipeline` | 药品 / 器械管线、研发进度 | ❌ | 主语义是阶段与适应症，不是金额 |
| `other` | 无法归入以上类型 | ❌ | 不进入核心分母，避免用杂表拉低/拉高覆盖率 |

> `table_type` 是**规则分类 v1**，全库 3,148 张表**未逐表人工核验**；后续阶段 2/3 用人工抽样校准，校准后必须升版本号，不静默改口径。
>
> **2026-10-17 修正记录**：初版规则把含 `EPS/PE` 的预测表/财务表判成 `valuation`（全库 402 张 `valuation` 含财务指标、327 张含 `2025E` 等预测列）。已改为：显式报表标题 → 预测标记 → 明确“估值”标题 → 财务指标 → 估值词。修正后 `forecast` 531 张、`financial_statement` 597 张、`valuation` 202 张。

### 2.3 `table_scope`

| 值 | 定义 |
|:--|:--|
| `stock` | 单一个股主体 |
| `industry` | 行业 / 市场汇总，或多主体横向对比 |
| `mixed` | 同时包含个股与行业/多主体语义 |
| `unknown` | 证据不足 |

判定顺序：`doc_type` 先验 → 表内股票代码数量 → 表内行业词。当前 `unknown=0` 是因为 473 篇文档都有 `doc_type`，不是因为表级分类已经完美。

### 2.4 `unit` / `unit_source` / `unit_candidates`

- 回退链固定为：`cell`（表头/单元格）→ `caption`（表标题/研报标题）→ `footnote`（表下注释）→ `none`。
- `unit_source` 取值：`cell` / `caption` / `footnote` / `none` / `multi`。
- 同一张表出现**多个不同货币单位**：`unit=None`、`unit_source="multi"`、`unit_candidates` 保留全部候选；**不取众数、不猜、不静默选第一个**。
- 外币只记录原文（如 `百万美元` / `百万港元`），本阶段不做汇率折算；`unit_factor` 语义不变。
- 实测 `unit_source`：`none 2047 / cell 803 / multi 298`；`caption` 与 `footnote` 单独命中为 0（有单位时通常表内也有，`cell` 优先）。这是观测结果，不是回退链未实现。

> 298 张 `multi` 中，104 张是 `financial_statement`、98 张是 `valuation`、68 张是 `forecast`、24 张是 `ranking`、3 张是 `industry_summary`、1 张是 `pipeline`。它们不是“脏数据”，而是**表级单值单位无法表达行级差异**的证据：例如同一张财务表里“营业收入(百万元)”和“摊薄EPS(元)”并存。阶段 2 的**行级自包含事实 + `anchor_cells`** 才是正确解法；阶段 1 只用 `multi` 保守标记。

### 2.5 `report_period` 与 `publish_year`

| 字段 | 语义 | 表级 | chunk 级 |
|:--|:--|:--|:--|
| `report_period` | 这篇内容评论的**报告期** | `Table.report_period`：**表内证据**（表标题/表头/首列/表体） | splitter 字段：文档级 `title / title_weak / body` + 表内，检索实际使用 |
| `publish_year` | 研报**发布年** | 从文档元数据带入 | 同左；行业研报的期间过滤键 |

**不可互除**：表级 `report_period` 是“表内能不能看出来”，chunk 级是“检索时实际拿到的字段”。例如 `stock|financial_statement|stock` 表级 43.8%、chunk 级 81.2%，差在文档标题/正文推断，不是表解析退化。

### 2.6 表级 `stock_code` 的特殊说明

表级 `stock_code` 只统计**表内出现的代码**；chunk 级 `stock_code` 从文档元数据继承。因此 `stock|financial_statement|stock` 表级为 0.0%、chunk 级为 100.0% 是**预期现象**，不是代码丢失：

- 表级：财务表本身通常不写股票代码 → 用于判断 `table_scope` 的表内证据；
- chunk 级：检索过滤使用文档元数据 → 用于主体过滤。

报告不得把这两个数放在同一列比较。

## 三、覆盖率口径（硬规则）

1. 每个数字必须写清：**分子 / 分母 / 适用域 / 排除项**。
2. 表级分母 = **表数**；chunk 级分母 = **表格块数**；全库 chunk 分母 = 所有 chunk。三者不可互除。
3. `unit` 核心分母 = `table_type ∈ {financial_statement, valuation, forecast, industry_summary}`；排除 `ranking / pipeline / other`。这个定义写死在契约里，不能为了好看临时换分母。
4. 历史报告 `元数据覆盖率报告_20261016.md` 的 **65.0%** 保留原义：**当前正则口径下，3,148 张表里 2,047 张零候选**，不是“绝对没有单位”的物理事实；正则漏检上界见该报告 §6.4。
5. 旧口径 878 张“可提取”中，75 张在新口径下判为 `multi`；因此新口径 `803 + 298 = 1,101` 张有候选，旧口径 `878 + 223 = 1,101` 张有候选。**总数不变，分类更严格**。
6. 表级与 chunk 级字段名相同但语义不同时，报告必须加列名后缀或脚注（如“表内识别” / “检索字段”）。

## 四、关键分层读数（表级）

| 分层 | n | unit | report_period（表内） | publish_year | metric_name |
|:--|--:|--:|--:|--:|--:|
| `stock|financial_statement|stock` | 377 | **51.2%** | 43.8% | 100.0% | 100.0% |
| `stock|valuation|stock` | 97 | 0.0% | 44.3% | 100.0% | 96.9% |
| `stock|forecast|stock` | 517 | 43.3% | 28.1% | 100.0% | 99.6% |
| `industry|industry_summary|industry` | 611 | 5.2% | 35.5% | 98.7% | 9.2% |
| `industry|valuation|industry` | 104 | 26.9% | 28.8% | 98.1% | 85.6% |
| `industry|pipeline|industry` | 440 | 5.2% | 24.3% | 94.1% | 44.1% |

解读：

- **个股财务报表的 unit 不是主要瓶颈**（51.2%），剩余 48.8% 里一部分是真实混用（多单位），一部分是表内确实没写；阶段 2 行级事实会把“表级单值”升级为“行级单位”。
- **行业汇总表 unit 低是类型/语料属性**：这类表大量是行业指标、排名、策略表，`publish_year` 才是主期间键；不应为了 unit 覆盖率把 `ranking/pipeline` 塞回分母。
- **预测表的表内报告期低**（28.1%）不等于检索不可用；chunk 级 71.8% 已包含文档标题/正文推断，但预测期（2025E/2026E）不能当实际报告期，阶段 2 需在行级事实中区分 `实际期/预测期`。

## 五、下游用例合格线（契约 v1）

| 用例 | 达标线 | 当前基线 | 口径备注 |
|:--|:--|:--|:--|
| 表格数值问答（RAG） | 27 题实体评测 top-10 真内容 **≥6.0**；4 条严重题 **≥8**；空上下文 **≤1** | 真内容 **4.93**；4 条严重题 **8–10** | 沿用 2026-10-16 的 27 题实体口径；不为达标改题 |
| 行级事实 / 证据定位 | `anchor_cells` 可定位率 **100%**；top-10 至少 1 条正确 anchor 的题 **≥90%**；主体/期间错配 **0** | 尚未建立 | 阶段 2 建立；anchor 必须能回到原表行列 |
| L5 检索排序 | 300 条标注完成后 HR@10 **≥0.40**、MRR **≥0.30**、nDCG@10 **≥0.35**；相对 26 条可比子集不退化 | 26 条可比子集 HR@10 **0.3271** / MRR **0.2565** / nDCG@10 **0.3014** | 300 条未完成前不发布正式 L5 数字 |
| claim faithfulness / 引用核验 | claim-evidence 覆盖率 **100%**（无证据显式标）；人工抽检 20 条支持率 **≥0.90**；引用主体/期间一致率 **≥0.95** | 正式基线待阶段 5 | 不以“引用存在”代替“引用支持 claim” |

> 这些线是**工程判定线**，不是行业标准；改线必须写变更记录并升契约版本，不能跑完再挑口径。

1. 本契约涉及的 `unit_source`、`table_type`、`table_scope`、`unit_candidates` 已写入 `Table.to_payload()` 和表格 chunk metadata；**必须重建索引才生效**。
2. 阶段 1.2（unit 回退）与 1.4（`table_scope`）合并为**一次重建**，不重复重建。
3. 建议新集合名 `research_reports_v4_contract`，不覆盖 `v3_structured` / 线上 `v3_full`。
4. 已执行（2026-10-17）：`research_reports_v4_contract` 重建 **12,301 点 / 425.9s**；抽查 `t1` 为 `unit=None / unit_source=multi / candidates=[元, 百万元]`，`t2` 为 `table_type=forecast`；`table_type / table_scope / unit_source / unit_candidates` 四字段均存在，表格 chunk 与 `table_id` 可对应。

## 七、本阶段明确不做

- 不取众数、不猜单位、不做汇率折算。
- 不改写历史报告 `元数据覆盖率报告_20261016.md` 的 65.0%；新报告只做增补。
- 不把 `ranking / pipeline / other` 塞回 `unit` 核心分母来“提升覆盖率”。
- 不在阶段 1 做行级单位、行级事实、多阶段检索；这些是阶段 2/3。
- 不用 `table_type` 规则分类冒充人工标注；后续人工抽样校准后升版本。
