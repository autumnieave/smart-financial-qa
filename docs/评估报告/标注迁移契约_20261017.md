# 标注迁移契约（阶段 2）

> 日期：2026-10-17　任务：B-60（数据管道重构 · 阶段 2）
> 代码：`eval/label_migration.py`　测试：`tests/test_label_migration.py`

## 一、目标

数据结构从「整表 chunk」升级为「整表父块 + 行事实子块」后，旧标注（人工判定、缺陷记录）
不能靠文本相似度重新猜一遍——那会把「标注迁移」变成「重新标注」，且无法复核。

本契约只做一件事：**按坐标把旧标注映射到新 anchor**，映射不上的显式进人工复核。

## 二、匹配顺序

1. `source_file + table_id + row_index + col_index`（精确）
2. 表 ID 变化时：`source_file + table_caption + row_index + col_index`（二次匹配）
3. 旧标注只有 `row_start / row_end` 时：按行区间落到新 anchor

每一步命中**恰好一条**才继续；命中多条即 `ambiguous`，不猜。

## 三、三态输出

| 状态 | 含义 | 处置 |
| --- | --- | --- |
| `mapped` | 唯一命中新 anchor | 自动迁移，保留原判定 |
| `ambiguous` | 命中多条（表 ID 变化 + 标题重复 / 行区间跨多行） | 进人工复核，不自动选 |
| `unmapped` | 无命中 | 进人工复核，不静默丢弃 |

`migrate_labels()` 返回逐条结果与汇总计数，后两态必须出现在复核清单里。

## 四、输入要求

旧标注至少需要：

- `source_file`（或 `file_path` / `filename`）
- `table_id`（或核心字段 `source`）
- `row_index` + `col_index`（单元格级）
- 或 `row_start` + `row_end`（行区间级）

字段名兼容在 `eval/label_migration.py` 内集中处理，调用方不需要改历史数据格式。

## 五、当前 L5 标注的适用性（必须写清）

当前 L5 新集合标注工作单（本地资产，不入库）的 10 条人工判定是「题 × rank 片段」结构，
**不含 `table_id / row_index / col_index`**，因此：

- 它们**不是**本迁移契约的输入；
- 不能声称「旧标注已迁移」；
- 阶段 3 检索冻结后重新生成工作单时，工作单需带坐标栏，届时新标注天然满足契约。

## 六、阶段 3 的使用方式

1. 多阶段检索返回行级 anchor 后，用 `chunk_id` / `table_id + row + col` 回表；
2. 人工标注直接标在 anchor 坐标上；
3. 后续任何表结构变化，先跑 `migrate_labels()`，`mapped` 自动迁移，
   `ambiguous / unmapped` 进复核清单，再决定是否重标。

## 七、测试覆盖

`tests/test_label_migration.py`（5 条）：

- 精确坐标命中 → `mapped`
- 表 ID 变化 + 标题匹配 → `mapped`
- 同标题多表 → `ambiguous`
- 行区间跨多条 anchor → `ambiguous`
- 无命中 → `unmapped`

全部离线，不依赖 Qdrant / MySQL / LLM。
