# 实体定向重试（2026-10-18）

## 一句话结论

**实体缺失不再靠全局 400 扩召回，改为“内存 BM25 按点名主体取表 + 合并重审”。B2007|2 实体覆盖 2/2，热态延迟 382–880ms（均值 598ms），低于 1s；全局 400 均值 1,790ms，旧 100→200→400 回退 2,871ms。其他 11 题 top-10 与改造前逐题 10/10 完全一致。**

## 一、为什么不直接用 Qdrant `stockName` 过滤

先做了原型：`query_filter={"should": [{"key": "stockName", ...}]}` + `coarse_k=100`：

- 延迟 4.1–6.8s，比全局 400 还慢；
- `coarse_k=100` 时 top-10 只覆盖华润三九，白云山仍为 0/2。

原因是 `stockName` 没有可用的 payload 索引，过滤退化成全量扫描，且行证据阶段仍按候选表重算。**不能作为 <1s 方案。**

## 二、最终方案

实体审计返回 `retry_entity` 后：

1. 用**内存 BM25 表索引**（3,148 张表）检索缺失主体名，耗时 155–176ms；
2. 先保证每个缺失主体至少取一张表，再用其余命中补足 top-10；
3. 与当前候选表按 `table_id` 去重合并（定向命中优先）；
4. 立即用合并后的候选重审：
   - 覆盖 2/2 → `accept`；
   - 仍缺 → `reject_with_reason`；
   - 出现指标/期间 mismatch → 继续原有 `retry_table` 逻辑。

不查 Qdrant、不做全局 `coarse_k` 扩召回、不改变其他题的检索路径。

## 六、边界

1. **热态 vs 冷态**：B2007 端到端首次运行 `recall=1,808ms + entity_retry=428ms`，总 2,247ms；热态 382–880ms。线上需要预热（BM25 索引 + Qdrant/向量缓存），否则首题仍可能 >1s。
2. **依赖 BM25 索引**：没有 BM25 时回退旧 100→200→400（2,871ms）。线上要获得 <1s，必须启用表级 BM25。
3. **依赖 `known_entities`**：未传公司名词表时不做实体审计，也不会触发定向重试。
4. **精确主体名**：BM25 取表后仍用 `stockName/stockCode` 精确校验；别名需先在 `known_entities` 中归一。
5. **只修检索层**：生成层仍需 `--retrieval-query`（已实现）；否则答案仍可能选错主体。
6. **本轮未改主口径**：90.62% 仍是冻结主口径；实体定向重试是 v2 条件路径的线上候选方案，是否提升为默认口径待确认。

## 七、决策建议

- **不再考虑全局 400 默认**：延迟 1.79s 均值、3.34s 最大，且会改变 8/12 题 top-10。
- **采用实体定向重试**：B2007 热态 <1s，其他题零影响，只对实体缺失触发。
- **v2 的线上化条件**：表级 BM25 开启 + `known_entities` 传入 + 生成使用 `retrieval_query` + 进程预热。
- 在上述条件未全部满足前，主口径保持 **90.62%**；满足后可重跑全 12 题，决定是否把 v2 提升为主口径。
