# 元数据覆盖率报告：分层版（2026-10-17）

> **一句话**：全库 3,148 张表，`unit` 可提取 **803 张（25.5%）**、零候选 **2,047 张（65.0%）**、多单位 **298 张（9.5%）**；按 `unit` 适用域（1,963 张）算是 **31.5%**。个股财务报表 `unit` **54.7%**，行业汇总表 `unit` 只有 **5.2%** 但 `publish_year` **98.7%**——覆盖率必须按分层看，不能再用一个全库数字代替。
>
> 本报告是 `元数据覆盖率报告_20261016.md` 的**分层增补**，不修改历史报告的 65.0% 口径。

## 一、口径与分母（先看这里）

| 口径 | 分子 | 分母 | 本报告用途 |
|:--|--:|--:|:--|
| 表级 `unit` | `unit` 非空的表 | 3,148 张表 | 判断“表里能不能提取出一个单位” |
| 表级 `unit` 适用域 | 适用域内 `unit` 非空的表 | 1,963 张表 | 排除 `ranking/pipeline/other` 后的核心分母 |
| chunk 级 `unit` | 表格 chunk 的 `unit` 非空 | 5,739 个表格 chunk | 检索时实际可用的字段 |
| chunk 级全库 | 全部 chunk 的字段非空 | 12,301 个 chunk | 只用于总览，不与表级互除 |

**适用域定义**：`table_type ∈ {financial_statement, valuation, forecast, industry_summary}`；排除 `ranking`（排序/涨跌幅）、`pipeline`（药品/器械管线）、`other`。这是契约 v1 的固定分母，不因报告结果调整。

**不可互除**：表级 25.5% 与 chunk 级 26.9% 看着接近，但分母分别是“表”和“表格 chunk”；`stock|financial_statement|stock` 的表级报告期 43.8% 与 chunk 级 81.2% 也不是同一件事（前者只算表内证据，后者含文档标题/正文推断）。详见 `数据管道契约_分层口径_20261017.md`。

## 六、关键读数

### 6.1 个股财务报表：unit 不是主瓶颈

`stock|financial_statement|stock`：

- 表级 377 张，`unit` **51.2%**；
- 表级 `report_period` **43.8%**，chunk 级 **81.2%**——差在文档级标题/正文推断，不是表解析退化；
- 表级 `stock_code` **0.0%**，chunk 级 **100.0%**——表内不写代码，chunk 从文档元数据继承；这是预期口径，不是缺陷。

剩余 48.8% 的 `unit` 缺口里，一部分是真实混用（`multi`），一部分是表内确实没写单位。阶段 2 行级事实会把“表级单值单位”升级为“行级单位 + 锚点”，不会靠猜提高表级覆盖率。

### 6.2 行业汇总表：unit 低、publish_year 高

`industry|industry_summary|industry`：

- 611 张表，`unit` **5.2%**，`publish_year` **98.7%**，`metric_name` **9.2%**；
- 这类表大量是行业指标、策略汇总、横向对比，主期间键是发布年；用 `report_period` 或货币单位去要求它，会把口径做错。

### 6.3 估值表：单值单位不成立，多单位是常态

`industry|valuation|industry` 表级 `unit` **26.9%**，`stock|valuation|stock` **0.0%**（97 张纯估值卡片，86 张 multi + 11 张零候选，没有一张是单值单位）。估值卡片常同时出现“股价（元）”“总市值（百万元/亿元）”，所以表级单值单位不成立；`multi` 中 valuation 98 张、financial_statement 104 张、forecast 68 张。这不是提取失败，而是表级单位模型不够细。

### 6.4 预测表：实际期与预测期不能混

`stock|forecast|stock` 表级 `unit` 43.3%、表内 `report_period` 28.1%，chunk 级报告期 71.8%。预测表常以 `2024A/2025E/2026E` 为列，不能把 `2025E` 当实际报告期；阶段 2 行级事实必须显式区分 `实际期/预测期`。

## 七、质量自检

| 检查 | 结果 | 判定 |
|:--|--:|:--|
| 报告期晚于发布年（不可能） | 0 块 | ✅ |
| 无法比对发布年 | 4 块 | 不判断、不误杀 |
| 表级 `unit` 候选总数 | 803 + 298 = 1,101 | 与旧口径 878 + 223 = 1,101 闭合 |
| 多单位抽样 | 5 张完整表头人工查看 | 均为真实“同一表不同指标不同单位” |
| 表格结构全库比对 | 3,343/3,343 零差异（历史报告） | 沿用，不重复 |

**878 → 803 的解释**：旧 `legacy` 口径按“第一个来源”取单一单位，878 张可提取、223 张多单位；新 `fallback` 口径把同表另一种货币单位也纳入候选，75 张从“单一”变成 `multi`。因此 803 + 298 = 1,101，与旧口径的 1,101 张有候选完全一致。**这是更严格，不是覆盖率退化。**

多单位样例（5 张抽检）：

- `2024年业绩符合预期，大健康业务打造新增长极.md#t1`：收盘价“元” + 总市值“百万元”；
- `2024年净利润YOY+35%...md#t1`：A股市值“亿元” + 每股净值“元”；
- `2024年年报业绩点评...md#t5`：营业收入“百万元” + 摊薄EPS“元”；
- `公司事件点评报告...md#t2`：预测指标“百万元” + EPS“元”；
- `医药生物行业周报...md#t1`：自由流通市值“亿元” + 收盘价“元”。

## 八、限制与边界

1. **机器统计，不是逐表人工核验**：3,148 张表的 `unit` 提取是正则 + 规则，未做全量人工确认；结论用于工程决策，不用于对外宣称“单位覆盖率已达 X%”。
2. **正则漏检上界**：历史报告 §6.4 已给出抽样与漏检上界；本报告不重复抽样，只沿用同一正则口径。
3. **`table_type` 是规则 v1**：未逐表人工校准；阶段的后续工作用人工抽样校准，校准后升版本。
4. **`multi` 抽样只有 5 张**：用于确认“不是正则假阳性”，不足以估计全库 `multi` 的错误率；阶段 2 行级事实会自然消化这部分。
5. **`caption/footnote` 命中为 0**：是观测结果，不代表回退链未实现；有单位时通常表内也有，`cell` 优先。
6. **重建状态**：本报告统计在重建前完成；随后已用同一代码重建 `research_reports_v4_contract`（12,301 点 / 425.9s），payload 四字段与多单位 `unit=None` 抽查通过。
