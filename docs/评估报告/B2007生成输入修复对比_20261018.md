## 一句话结论

**`--retrieval-query` 开关已加，默认行为不变；B2007|2 用上下文感知生成后，答案从“选取云南白药/江中药业”变为“华润三九 vs 白云山”，claim faithfulness 100%（单题 20/20、全量重跑 14/14）。全 12 题 v2 题均 99.65%（124/125 claims）；ASCII 刻度行遮罩修复后重评为 100%（124/124）。90.62% 与 v2 两个口径并存：v2 的增益主要来自 B2007|2 依赖 400 扩召回，线上默认 coarse_k=100 不触发；同分母 11 题只 +0.76pp。本轮不替换 90.62% 主口径。**

## 一、代码改动

`eval/a_regenerate_answers.py`：

- 新增 `--retrieval-query`（`store_true`），默认关；
- `generation_query = retrieval_query if use_retrieval_query else question`；
- 首次生成和实体修复生成都使用 `generation_query`；
- 单题记录新增 `generation_query` 字段，summary 的 `retrieval_config` 新增 `generation_query` 标识；
- 未改 prompt、模型、温度、检索配置。

默认不传 `--retrieval-query` 时，`generation_query == question`，与改动前完全一致。

## 四、B2010|4 的 -4.17pp 不是答案退化

v2 中 B2010|4 唯一未支持的 claim 是：

```text
             0        1000       2000       3000       4000
```

这是答案里 ASCII 柱状图的**坐标轴刻度行**，不是答案断言。该行被 claim 提取器当成数字 claim，计入 `1/24` 未支持。

**已修**：`is_structure_noise` 增加“纯数字序列行”识别——连续 3 个以上数字、无中英文文字（无指标名）、无 `%`/`‰` 单位时，不作为数字 claim。重评结果：

- B2010|4：23/24 → **23/23 = 100%**（该行从分母移除）；
- v2 全 12 题：124/125 → **124/124 = 100%**。

注意：准确写法是 **124/124**，不是 125/125——遮罩的语义是“这行不是 claim”，所以它同时从分子和分母消失。v1 主口径复算不受影响，仍为 **76/78 = 90.62%**。详见 `docs/评估报告/B2010评测器ASCII遮罩_20261018.md`。

## 五、边界与口径声明

1. **v1/v2 是两次独立生成，不是严格配对实验。** 6 道无上下文题的 `generation_query == question`，生成输入逐字相同，差异只能来自采样；6 道有上下文题的生成输入按设计改变，逐题对比才是本改动的有效证据。
2. **claim 分母从 78 变为 125。** v2 答案更长、信息更多，claim 数自然增加；题均是主比较口径，claim 级仅作辅助，不能把 97.44%→99.20% 当成同一分母的提升。
3. **v1 的 90.62% 含 B2007 零 claim 记 0 的保守约定。** v1 剔除 B2007 后 11 题为 98.86%；v2 同口径为 99.62%，实际提升 +0.76pp。对外仍保留 90.62% 作为冻结主口径。
4. **B2007 v2 的 1.0 只证明“答案与证据一致”。** 线上默认 `coarse_k` 仍是 100；若线上不接实体审计的 400 扩召回，B2007 仍会在检索层失败。面试口径必须说“检索层已修、生成诊断验证通过、待合并”，不能说“已修复”。
5. **90.62% 与 99.65% 两个口径并存，不互相替换。** 90.62% 是保守主口径（B2007|2 安全拒答记 0，可复现）；99.65% 是 v2 候选口径（上下文感知生成 + B2007 依赖 400 扩召回）。v2 的 +9.03pp 里 +8.33pp 来自 B2007|2 的 0→100，而它依赖 400 扩召回；线上默认 `coarse_k=100` 不触发。同分母 11 题为 98.86%→99.62%，只 +0.76pp。是否把条件重试接入线上，见 `docs/评估报告/400扩召回延迟评估_20261018.md`；在决策前不切主口径。
