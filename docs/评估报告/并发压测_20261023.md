# Locust 50 并发压测（2026-10-23）

## 结论

**[SKIP] 本轮未执行压测。**

阻塞原因：

1. `.venv` 未安装 `locust`（`ModuleNotFoundError: No module named 'locust'`）；
2. API `http://localhost:8000/health` 超时，无法作为压测目标；
3. Qdrant `localhost:6333` 不可达，即使启动 API，`/chat/stream` 也无法完成真实检索。

因此本报告**没有** P50/P95/P99、错误率或瓶颈归因数字。压测脚本已落盘，依赖恢复后可直接执行。

## 一、脚本

`eval/locustfile.py`：

- 用户数：50（由命令行 `-u 50` 控制）；
- 每秒启动：5（`-r 5`）；
- 持续时间：2 分钟（`-t 2m`）；
- 目标：`POST /chat/stream`；
- 成功判定：HTTP 200 且 SSE 流出现 `done`；
- `error` 事件、无 `done`、连接异常都记失败；
- 支持 `LOCUST_API_KEY`（配置了 `API_KEYS` 时）。

## 二、恢复后的执行命令

```powershell
.\.venv\Scripts\python.exe -m pip install locust
$env:LOCUST_HOST="http://localhost:8000"
$env:LOCUST_API_KEY="your-key"   # API_KEYS 启用时必填；未启用可留空
.\.venv\Scripts\locust.exe -f eval/locustfile.py --headless -u 50 -r 5 -t 2m `
  --host $env:LOCUST_HOST --csv 训练结果数据/locust_20261023
```

执行前建议：

- 压测专用 key 的 `API_RATE_LIMIT_PER_MINUTE` 调高，或临时关闭鉴权；否则 50 并发会被 10 req/min 限流，测到的是限流器不是系统容量；
- 确认 Qdrant、MySQL、DashScope 都可用；
- 开启步骤 1 的结构化日志，压测后可用 `eval/log_aggregate.py` 拆分检索/精排/生成瓶颈。

## 三、恢复后应产出

| 指标 | 来源 |
| --- | --- |
| P50 / P95 / P99 端到端延迟 | Locust CSV 或结构化日志 `total_ms` |
| 错误率 | Locust `failures` / 总请求 |
| 检索/精排/生成占比 | `训练结果数据/logs/YYYYMMDD.jsonl` + `eval/log_aggregate.py` |
| 瓶颈归因 | 若 `retrieval_ms` 占比高 → 检索段；若 `generate_ms` 高 → 生成段；若 429 多 → 限流配置 |

## 四、边界

- 当前限流是单进程内存实现；50 并发压测如果只起一个 uvicorn worker，限流计数是准的；多 worker 会各自计数。
- 本轮不把“脚本存在”当成“压测通过”；报告状态保持 [SKIP]，直到真实跑出 CSV。
- 不安装 locust 是遵循本轮“缺失依赖先记录、不硬扛”的纪律；安装后再跑，结果单独更新。
