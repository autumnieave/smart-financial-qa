# A 类扩样拒答与证据选择归因（2026-10-18）

## 一句话结论

**5 道题全部是检索/证据覆盖问题，不是生成编造，也不是“优先同文档/同机构”提示词缺失。** 把金标表补进 top-10 上下文后，5 题全部 strict 1.0 且答案包含金标值；其中 02/07/08 会同时列出两篇研报的不同预测，说明生成侧能处理多源。可快速修的是 **03/04 的同文档兄弟表召回**（模拟验证通过，但不是 1 行，需 file→table 倒排 + 指标/期间筛选 + top-10 替换规则，约 30–50 行 + 单测）；**02/07/08 的金标报告根本不在向量 top-100 / BM25 top-60**，属报告级召回边界，不阻塞简历阶段。

## 一、归因方法

对 5 题分别检查三层候选：

1. **向量表级 top-100**：`MultiStageRetriever._search(query_vec, chunk_type=table, limit=100)`
2. **表级 BM25 top-60**：`table_bm25.retrieve(question, top_k=60)`
3. **最终 top-50**：与线上一致的 `retrieve_with_iteration(top_k=50, rerank=False)`

再做一次**金标补入模拟**：保持原 top-10 不变，把 gold 表追加到上下文末尾，用同一 `LLMGenerator` 重生成，检查 strict faithfulness 与 gold-value match。该模拟只用于归因，不进入 22 题主口径。

产物：

- `训练结果数据/stage5_measure/a_expand_attribution_candidates.json`
- `训练结果数据/stage5_measure/a_expand_gold_append_simulation.json`

## 四、修复分级

### 4.1 可小改：同文档兄弟表召回（03/04）

**不是 1 行。** 需要：

1. 在 `MultiStageRetriever` 初始化时建 `file → [table_id]` 倒排（可直接复用 BM25 docs 的 payload）；
2. 最终 top-k 选定后，对每个已命中文件，找同文件、同 query 指标（必要时同期间）的兄弟表；
3. 若当前 top-k 没有任何表覆盖该指标/期间，用兄弟表替换最后一名（保持 top-10）；
4. 加开关（默认关）+ 单测（不得误加同文件无关表）。

预计 30–50 行 + 2 个单测，1–2 小时。模拟收益：新增 10 题 grounding 90% → 100%，gold-value 5/10 → 7/10；22 题 v2 端到端模拟约 99.2%。**该收益不计入当前口径**，需实现并通过 12/22 回归后才能替换。

### 4.2 已知边界：报告级召回（02/07/08）

金标报告不在向量 top-100 / BM25 top-60。修复需要报告级召回（标题/摘要/元数据）或按 `stock_code + publish_year + “预测”` 做报告路由，属于结构性改动；不是调 `coarse_k` 能解决的问题（400 扩召回延迟 +2.43s，已否决）。

**处置：写入已知边界，不阻塞简历/面试阶段。**

### 4.3 不需要改生成提示词

补入 gold 后，02/07 会自动并列两篇研报的不同预测，08 会改用 gold。没有证据表明需要“优先同文档/同机构”的生成约束；在证据不全时加这种约束只会掩盖召回问题。

## 五、对 22 题口径的影响
