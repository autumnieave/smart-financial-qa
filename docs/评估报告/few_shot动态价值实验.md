# 动态 Few-shot 价值证明实验（B-39）

> **实验前提修正**：原 B-16 的对照实验未生效：`SQL_GEN_SYSTEM_PROMPT` 内无示例，所谓「静态基线」实为无示例。本轮重新定义三态：**none（无示例）/ static（固定示例，token 量对齐 dynamic）/ dynamic（按题型检索）**。**唯一变量 = 是否按题型检索**。

- 执行日期：2026-09-11｜脚本：`tools/data_scripts/few_shot_value_experiment.py`｜样本：golden v1 20 题（跨期趋势 7 / 对比排名或阈值 7 / 多指标绑定 6）
- 成本闸门：`QUERY_CACHE_ENABLED=false`，每题每组 1 次生成（失败最多重试 1 次），共 **60 次生成**，实测均耗时 4.5–5.1 s/次
- 产物：`训练结果数据/few_shot_value_experiment.jsonl`（逐题逐组）、`_summary.json`（汇总）

## 1. 实验设计

三组除「示例注入方式」外**完全同参**（同一 metric_plan、同一提示词、同一 schema/连接、`temperature=0.1`、`--retries 1`）：

| 组 | `AGENT_FEWSHOT_MODE` | 注入内容 | 条数 | 提示词增量 |
| --- | --- | --- | --- | --- |
| none | `none` | 无示例（= 当前默认行为） | 0 | 0 字符 |
| static | `static` | **固定示例、不检索**（`per_type`，不同题型各 1 条） | 2 | +2157 字符 |
| dynamic | `dynamic` | **按题型检索**注入（B-16 原设计） | 2 | +1590 字符（随题变化） |

设计要点：
1. 每题**只做 1 次指标标准化**，结果三组共用 → 消除标准化噪声；
2. static 与 dynamic **同为 k=2**，token 量级对齐 → 避免「示例多寡」混淆「是否检索」；
3. 「首次生成成功率」取自 `tools.native_financial._gen_stats()`（attempts / first_ok），**不额外调用 LLM**；
4. 按题型分组使用运行时真实 `metric_plan` 的 `predict_type`，不用字符规则近似。

## 5. 失败归因（四类，必须分开看）

| 类 | 题号 | 现象 | 归因 | 是否影响组间结论 |
| --- | --- | --- | --- | --- |
| ① 样本不可答 | B2028-Q1 | 三组均 `attempts=0`，0.00s，报「库外指标（库内无对应字段）: 老年病相关药品收入占比」 | 该题所需字段**库内不存在**，被 B-31 库外守卫确定性拦下，与 few-shot 无关 | 否（三组同值，仅浪费 3 次生成）——但属**样本选取失误**，应由 `B2008/B2011` 类可答阈值题替代 |
| ② 结构核验误伤 | B2008-Q1、B2014-Q1 | 三组同判 `rank_has_limit=False` | 两题实为「阈值筛选 / 多对象对比」，按 A~E 规则**本就不应带 LIMIT**；而 `predict_type` 判为 `rank` → 核验器据此要求 LIMIT。**属核验口径过严的假阳性，非模型缺陷** | 否（三组同值），但核验器需修正 |
| ③ dynamic 首跑失败、重试恢复 | B2055-Q1、B2057-Q1、B2071-Q1 | dynamic 首次 FAIL、`attempts=2` 后编译通过；耗时 10.2–11.5 s | 注入示例后生成结果**首次未过静态/编译校验**，带错重试才通过 | **是**——正是 dynamic 首跑通过率（80%）低于 none/static（90%）的全部来源 |
| ④ static 编译失败 | B2074-Q1 | static `F/F`，错误「字段 `net_profit_10k_yuan` 不存在于表 `income_sheet`（别名 t3）；SELECT 引用了未定义别名 t1」 | 固定示例（未按题检索）把字段/别名写法带偏，重试 1 次仍未收敛；none/dynamic 同题均通过 | 是——static 编译率（90%）低于另两组（95%）的唯一来源 |

## 6. 结论

1. **动态 few-shot 在本实验条件下没有优势，方向甚至略为不利**：首次生成通过率 **80%（16/20）**，低于 none 与 static 的 **90%（18/20）**；最终编译通过率与 none 持平（95%），结构正确率三组持平（85%）；平均耗时最高（5.06 s，比 none 慢 0.45 s）。
2. **「检索」这一变量本身没有产生可观测增益**：static（固定示例、不检索）与 dynamic（按题型检索）同为 k=2、token 量级相近，但 dynamic 并未比 static 更好——首次 80% vs 90%、编译 95% vs 90%、结构持平、耗时更高。**若目标是「用示例提升 SQL 生成质量」，当前证据不支持给检索器加分。**
3. **天花板效应是首要解释**：none 组（无任何示例）首次通过率已达 90%、编译 95%，留给示例注入的提升空间只有 1 题量级；在 20 题样本上无法体现差异。

    **局限**：本轮样本量 20 题、动态组失败集中在 3 题（B2055/B2057/B2071），不排除随机波动。结论「不建议默认开启」成立；「动态更差」的强度受样本量限制，不作为强结论。

**根因排查（对照任务预设的三个假设）**：

| 预设根因 | 本实验证据 | 判定 |
| --- | --- | --- |
| 检索器不准 | 检索命中率 **100%**（每题均注入 2 条、题型与预测类型一致） | **排除**——检索本身工作正常 |
| 示例库不够 | 库内仅 10 条（5 题型 × 2 条）；static 组用「类型固定」的 2 条同样拿到 90% 首跑 | **部分成立**——但"示例少"未导致 static 落后，说明瓶颈不在数量 |
| 题目太简单 | none 组首跑 90% / 编译 95% | **主要根因**——天花板效应，样本缺乏区分度 |

补充观察（**结构性代价**）：注入示例使提示词变长 1590–2157 字符，dynamic 组出现 3 次 10 s 以上长尾（B2055 10.16s、B2057 10.38s、B2071 11.47s），且这 3 次**恰好都是首次失败、需重试**的题——提示更长 ≠ 更准，反而增加了首跑不收敛的概率。

## 7. 建议

1. **不建议将 `AGENT_DYNAMIC_FEWSHOT` 默认开启**（对应 `AGENT_FEWSHOT_MODE=dynamic`）：现有证据不支持其增益，且首跑通过率更低、耗时更高。保持默认 `none` 是当前最优选择。
2. **若要做第二轮，先修三件事（否则只是重复本轮结论）**：
   - **换样本**：剔除 B2028-Q1（库外指标不可答），改为选取 **none 组首跑失败的题**（如 B2057-Q1 类比值题、B2071-Q1 类跨期题）作为「难例集」，制造区分度；
   - **扩示例库**：每题型从 2 条扩到 5–8 条，并让示例覆盖「跨表 JOIN / 比值区间 / 阈值筛选」等易错形态；
   - **修核验口径**：`rank_has_limit` 对阈值筛选/对比类问题属假阳性，应改为「仅当 `calculation.order_by` 存在且非 threshold 语义时要求 LIMIT」。
3. **保留三态开关作为可回退能力**：`AGENT_FEWSHOT_MODE` 已落地且默认行为逐字节不变，面试可作为一个「用对照实验否证自己的优化方向」的案例讲述。

## 8. 局限与诚实声明

- 样本 20 题、单次运行、LLM 温度 0.1（非确定性）：动态与静态的 1 题量级差异**不构成统计显著**；本轮只能得出「**未见增益**」，不能得出「检索有害」。
- `binding_relation` 仅命中 1 题（B2047-Q1），该题型结论不具代表性。
- 「结构正确率」为**规则口径**（非真值回查），且已知含 2 题假阳性（见 §5 类②）；若剔除该 2 题，三组结构正确率均为 15/18 = 83%。
- 本实验只覆盖「SQL 生成环节」，未覆盖 Agent 编排 / RAG 检索 / 答案生成；结论不可外推到全链路。
- 样本两处替换（2026-09-11 用户确认）：`B2032-Q1 → B2038-Q1`（原题涉 B-30 指标替换缺陷）、`B2053-Q1 → B2047-Q1`（原题涉 B-33/B-36/B-37 三重缺陷），以避免已知缺陷污染 few-shot 结论。

## 9. 面试口径（30 秒）

> 「我做过一轮 few-shot 的对照实验，结论是**否证**的：我原本想证明'按题型动态检索示例'有价值，就设了三组——无示例、固定示例、检索示例，唯一变量就是'是否按题型检索'，20 题 × 3 组 = 60 次真实生成。结果动态组的首次生成通过率反而最低（80% vs 90%），编译通过率持平，耗时还更高。排查下来不是检索器不准（命中率 100%），而是**题目太简单**——无示例组首跑就有 90%，天花板效应让示例注入没有发挥空间，而且提示词变长后首跑更容易不收敛。所以我没有把它默认打开。这个实验的价值不在'我优化了'，而在'我用可复现的对照证明了自己的优化方向暂时不成立'，以及我清楚下一步该换难例集、扩示例库再来一轮。」
