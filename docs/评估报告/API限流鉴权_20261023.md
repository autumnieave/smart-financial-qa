# API 限流与 Key 鉴权（2026-10-23）

## 结论

- FastAPI 中间件已加入 API key 鉴权与 **10 req/min**（可配置）滑动窗口限流。
- 单元测试覆盖：无 key → 401、错误 key → 403、正确 key → 200、超限 → 429、`/health` 免鉴权。
- 未配置 `API_KEYS` 时保持本地开发兼容（鉴权关闭）；配置后强制校验，不在代码里硬编码 key。

## 一、实现

| 文件 | 内容 |
| --- | --- |
| `src/utils/api_security.py` | `parse_api_keys` / `extract_api_key` / `SlidingWindowRateLimiter` |
| `src/app/api.py` | `api_key_auth_middleware`：鉴权 + 限流；结构化日志中间件仍在最外层，拒绝请求也会落日志 |
| `src/config/rag_config.py` | `API_KEYS` / `API_AUTH_ENABLED` / `API_RATE_LIMIT_PER_MINUTE` / `API_AUTH_EXEMPT_PATHS` |

### 配置

```env
# 逗号分隔；为空时本地开发不启用鉴权
API_KEYS=key-a,key-b

# 可选：显式开关；不设置时自动策略 = API_KEYS 非空则启用
API_AUTH_ENABLED=true

# 每个 key 每分钟请求数
API_RATE_LIMIT_PER_MINUTE=10
```

支持两种请求头：

- `X-API-Key: key-a`
- `Authorization: Bearer key-a`

免鉴权路径：`/health`、`/docs`、`/redoc`、`/openapi.json`、`/result`。

## 二、行为矩阵

| 场景 | 状态码 | 响应 |
| --- | ---: | --- |
| `API_KEYS` 为空（本地开发） | 正常放行 | — |
| 已配置 key，但请求无 key | 401 | `{"detail":"missing api key"}` |
| 已配置 key，但 key 不在白名单 | 403 | `{"detail":"invalid api key"}` |
| 已配置 key，key 正确且未超限 | 200 | 正常业务响应 |
| 同一 key 超过每分钟限额 | 429 | `{"detail":"rate limit exceeded","retry_after_seconds":...}` + `Retry-After` |
| `/health` 无 key | 200 | 健康检查正常 |

## 四、边界

- 限流是**单进程内存**实现；多 worker / 多副本部署时每个进程各自计数，需要 Redis 或网关级限流才能全局一致。
- 只对已配置 key 的请求限流；无 key 请求在鉴权层直接拒绝，不进入限流计数。
- key 不写入日志；结构化日志只记录请求路径/耗时/token，不记录 `X-API-Key`。
- 本轮未启动真实 uvicorn（Qdrant 不可用），接口行为由 FastAPI TestClient 的 stub pipeline 验证；中间件逻辑本身不依赖 Qdrant。
