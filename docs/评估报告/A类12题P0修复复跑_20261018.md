# A 类 12 题 P0 修复复跑：生成约束 + 实体覆盖 + 证据元数据

日期：2026-10-18

对象：A 类 12 题。P0 三项改动后重生成答案，再按同一套 claim faithfulness 评测（严格口径），并给出放宽口径诊断。

## 一、结论先行

**P0 的两个目标都发生了实质变化：**

1. **B2011|3 不再用“某企业”匿名补数**：答案现在点名“太极集团、昆药集团、寿仙谷”，并附公司/代码/报告期/表号。严格口径 18.75%，放宽口径 **56.25%**（P0 前 36.36%），达到“50%+”的 P0 验收线（按放宽口径）。
2. **B2007|2 主体漂移消失**：覆盖检查识别出“999/白云山 → 云南白药/同仁堂”，带约束重生成后，答案明确写“华润三九/白云山资料未覆盖”，不再替换主体。

| 指标 | P0 前 | P0 后 | 变化 |
|---|---:|---:|---:|
| 严格口径题均 | 73.02% | **68.09%** | -4.93pp |
| 放宽口径题均 | 91.71% | **94.39%** | +2.68pp |
| 数字 claim 数 | 100 | 107 | +7 |
| 实体漂移题 | — | **0**（前 2） | 清零 |

**严格口径下降不是答案退化，而是“答案更具体”后暴露了评测器的单位/四舍五入假阴性。** P0 后答案新增了公司名、报告期和更多可核验数字（claim 100→107）；严格评测器要求“数字同句带单位”，而表行的单位只在表头/标题里，且“亿元 vs 百万元/万元”的换算与四舍五入没有容差。放宽口径（允许单位变体、不要求同句带单位、证据配额 50）从 91.71% 升到 94.39%，说明真实支持率在改善。

**一句话：P0 修的是“匿名主体 + 主体替换”，这两点已修好；严格分低是 P1 评测器的问题，不应据此回退 P0。**

## 二、P0 改了什么

### 2.1 RAG prompt v2：三条硬约束

`src/prompts/rag.py` 新增回答要求 6–8：

6. 每个具体数字必须能在参考资料中找到；不得依据常识、记忆或行业经验补数。
7. 问题点名的公司/机构只能讨论这些主体；资料未覆盖时明确说明，不得替换成其他公司。
8. 不得用具体数字替“某企业/某公司/该企业/该公司”等匿名主体补全；没有主体名称时只做定性描述或说明证据不足。

版本：`RAG_PROMPT_VERSION=2026-10-18-v2`，包级 `PROMPT_VERSION=2026-10-18-v9`，registry 已同步。

### 2.2 实体覆盖检查 + 一次约束重生成

新增 `src/core/entity_coverage.py`（纯规则、零外部依赖）：

- 从 query+context 抽点名主体，从 answer 抽答案主体；
- `drift`：答案出现其他主体，且没有覆盖任何点名主体；
- `needs_repair`：`drift`，或答案完全没提点名主体；
- `build_entity_constraint()` 生成“只允许讨论点名主体；未覆盖就说资料未覆盖”的约束。

`eval/a_regenerate_answers.py` 在首轮生成后审计；需要修复时带约束重生成一次，并记录 `entity_coverage_before/after`、`entity_repair_used`。

### 2.3 证据元数据前缀：让模型知道“这张表属于谁”

新增 `src/core/evidence_context.py`，给每条生成证据加一行：

```
【公司：片仔癀｜代码：600436｜报告期：2024A｜表：首次覆盖报告.md#t9】
<整表正文>
```

- 评测脚本用它拼生成上下文；
- `src/pipelines/rag_pipeline.py` 的 `query()` 与 `conversational_query()` 也接入同一 helper，只影响生成上下文，不改 rerank 输入和引用正文；
- 这一步同时修好了 B2010|4：检索其实已经返回佐力药业的表，但正文里没有公司名，模型之前认不出来；加元数据后答案直接点名“佐力药业（300181）”。

### 2.4 测试

新增 `tests/test_entity_coverage.py`（5 条）、`tests/test_evidence_context.py`（4 条）；全量 **951 passed**。

## 四、B2011|3 专项：匿名问题修好了，但仍有少量真外推

**P0 前**：11 条 claim，答案是“某主体/某企业” + 具体数字，严格/放宽都 36.36%。

**P0 后**：16 条 claim，答案开头就是“太极集团（600129）、昆药集团（600422）和寿仙谷（603896）”，并引用表号；严格 18.75%，放宽 56.25%。

严格下降的原因：

1. **claim 变多**：11→16，答案更具体，新增了公司名和更多数字；
2. **单位换算**：`123.86 亿元` vs 表里 `12386.02 百万元`、`32.87 亿元` vs `3287.33 百万元`；严格评测器没有四舍五入容差；
3. **表头单位**：表行只写数字，单位在标题“（单位：百万元）”里，严格 `require_unit_context` 判为无证据；
4. **仍有真外推**：`4319/2437/2200/4600/2665/6.31` 等数字不在本轮 top-10 表里，属于模型补充的、证据未覆盖的数字；放宽口径仍会漏掉它们。

结论：**prompt 规则 8 解决了“匿名主体”，但没有完全解决“补证据外数字”。** 前者是 P0 目标，已达成；后者需要在 P1 做“数字不在证据 → 删除该断言/降级为定性”的硬闸门，或继续收紧 prompt。

## 五、B2007|2 专项：漂移消失，但根因是检索覆盖

- P0 前：问“999 与白云山”，答“云南白药与同仁堂”；`entity_coverage` 判定 drift。
- P0 后：约束重生成，答案明确写“华润三九/白云山资料未覆盖”，并列出资料里实际有的东阿阿胶/云南白药/同仁堂；drift 消失。
- 数字 faithfulness 为 0.0 是因为答案只有 1 条 claim 且不含可核验数字；这不是“答得差”，而是“证据不覆盖时的安全拒答”。
- **根因没有消失**：top-10 里确实没有华润三九/白云山的表。正确顺序应是“检索阶段实体过滤/重试 → 仍无则澄清或拒答”，而不是只靠生成后修复。这条登记为 P1 检索项。

## 六、B2010|4 与 B2006|2：元数据前缀的直接收益

- **B2010|4**：检索一直有佐力药业的表，但正文没有公司名，模型之前只能泛泛分析“不同公司”；加 `【公司：佐力药业｜代码：300181｜…】` 后，答案正确点名并给出 2022–2026 收入/增速，严格 76.47%。这是本轮最干净的“产品层收益”。
- **B2006|2**：追问“涨跌的原因是什么”，上下文是片仔癀；修复后答案点名片仔癀并引用首次覆盖报告，严格 75%、放宽 100%，drift 消失。

## 七、为什么严格口径反而下降

| 原因 | 证据 |
|---|---|
| 答案更具体，claim 100→107 | B2011|3 11→16；B2007|2 19→1（拒答） |
| 亿元/百万元/万元换算无容差 | B2006|2 的 2797/4325 在表里，严格仍判 missing；B2011|3 的 123.86 vs 12386.02 |
| 表行单位只在表头/标题 | `归属母公司净利润 | 2797 | ...` 行内无“元/万元/%”，严格 `require_unit_context` 拒绝 |
| 拒答题没有数字 claim | B2007|2 严格 0.0，但它不是“答错”，是“没有可核验数字” |

因此：**严格 68.09% 是下界，放宽 94.39% 是上界诊断；真实值在两者之间。** 不能拿严格 68.09 判断 P0 失败，也不能拿放宽 94.39 对外宣称“94% 忠实”。

## 八、P1 建议（下一步）

| 优先级 | 动作 | 解决 |
|---|---|---|
| P1-1 | 单位/四舍五入容差：亿元↔百万元/万元，±0.5% 或末位舍入；表头单位继承到行 | B2011|3、B2006|2、B2079|1 的严格假阴性 |
| P1-2 | 季度数字遮罩：`20xxQ[1-4]` 的 `3` 不作为独立数字 claim；单 claim 证据配额 5→按数字优先级分配 | B2080|1、B2006|2 的“3 占满配额” |
| P1-3 | 证据实体覆盖：top-10 不含点名主体时，先实体过滤/重试，再澄清/拒答 | B2007|2 的根因；B2010|4 已验证元数据有效 |
| P1-4 | 数字硬闸门：claim 的数字不在证据中 → 删除该断言或改定性 | B2011|3 剩余的 6–8 个真外推数字 |

P1 完成后重跑 12 题，再启动 A 类扩到 20+、B 类 75 题 SQL 路由评测集。

## 九、边界

1. **12 题 / 107 条 claim 是小样本**；每题只生成 1 次，prompt v2 + 元数据同时变更，P0 前后不是严格控制的 A/B。
2. **放宽口径不做实体-数值配对**，允许单位变体，可能高估；它只用于诊断，不替代严格口径。
3. **B2007|2 的 0.0 是“无数字 claim 的拒答”**，不能读成“忠实度 0”；报告表里已单列。
4. **B2011|3 仍有真外推**：P0 只解决了匿名主体，没有完全解决“补证据外数字”；56.25% 是放宽口径的 P0 验收，不是最终质量。
5. **不能把 68.09/94.39 直接和企业 0.80+ 对标**：语料、问题集、claim 粒度、证据口径都不同。
