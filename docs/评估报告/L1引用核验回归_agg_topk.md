# L1 引用核验回归：TABLE_AGG_TOPK 影响量化（2026-08-23）

> 目的：量化「表聚合 top-K 收敛」（`TABLE_AGG_TOPK=20`，默认档）对管线引用命中率的影响。
> 脚本：`tools/data_scripts/l1_topk_regression.py`（可重复执行）。

## 口径与方法

- 基准：golden v1（80 题 / 108 子问题，`database/golden/v1_2026-08-22.json`）
- 管线引用路径：检索（混合 200+200）→ 软过滤 → 表聚合 → Rerank(20→每文件≤2→10) → 引用构建 → 引用核验过滤；生成阶段置空（引用与生成无关，仅测引用路径）
- L1 核验：`CitationValidator`（comma 口径），指标 = 文件可溯源率 + 数字命中率
- 对照组：`TABLE_AGG_TOPK=20`（收敛） vs `TABLE_AGG_TOPK=0`（全量聚合）
- 数据文件：`<结果数据>/l1_topk{20,0}_refs.json` 与 `*_citation_report.json`

## 结果（修复索引错位 bug 后）

| 指标 | topk=20（收敛，默认） | topk=0（全量聚合） | Δ |
| --- | --- | --- | --- |
| 引用总数 | 1080 | 1080 | 0 |
| 文件可溯源率 | 100.0%（1080/1080） | 100.0%（1080/1080） | 0.0pp |
| 数字命中率 | **99.7%（9222/9248）** | **99.3%（4217/4246）** | **+0.4pp** |
| 零命中引用 | 0 | 0 | 0 |
| 「这是一个表格」占位引用 | 176（16.3%） | 723（66.9%） | — |

**口径说明（重要）**：全量聚合把 66.9% 的引用合并成无数字的表格占位（`text="这是一个表格"`），不参与数字命中分母，数字样本仅 4246 个；topk=20 保留了 903 条含数字引用（数字样本 9248 个，2.2 倍）。topk=20 在**更严格、样本更大**的口径下数字命中率仍持平略高。

## 结论

- **top-K=20 收敛对引用命中率无负面影响**：文件可溯源持平（100%），数字命中持平（99.7% vs 99.3%，样本更严格），同时表聚合阶段耗时 1.8s→1.1s（scroll 全量多表→3 次）。
- 首查/热查总耗时不受影响（~8.6~11.9s），答案关键数字抽检一致。
- 若未来回归发现个别「关键表格行排位靠后」的问题，可将 `.env` 的 `TABLE_AGG_TOPK=0` 临时恢复全量聚合（代价：首查聚合耗时 +0.7s 左右）。

## 附加发现：引用构建索引错位 bug（已修复）

回归过程中定位到一个真实 bug（非 topk 引入，但 topk=20 会暴露）：

- 症状：12 条引用「数字零命中」+ 更多部分命中假阳性。例如 B2003（主营业务收入上升的原因）返回引用 `业务收入比例（%）53.42% 51.22%...`，`paper_path` 指向「医药生物行业周报」，但该数字实际来自「个股研报-公司首次覆盖报告：夯实中药根基…」。
- 根因：`_aggregate_parent_table` 聚合后 `candidate_docs` 与 `search_results` 索引不再一一对应（多行合并为一张父表），但 `_build_reference_for_doc` 与文件多样性（`apply_file_diversity`）仍用 rerank 返回的「聚合后索引」直接取 `search_results` → `paper_path`/摘要取错文件。
- 修复：`_aggregate_parent_table` 额外返回 `index_map`（新候选位置 → 原始检索索引）；`_build_reference_for_doc` 按映射回取 payload；多样性文件键按候选列表对齐；无表格行的提前返回补空映射。
- 效果：topk=20 数字命中率 87.1% → **99.7%**（12 条零命中全部消除，B2003 修复为 4/4 命中且指向正确文件）；`pytest tests/ -q` → 65 passed（含新增 index_map 回归用例）。
