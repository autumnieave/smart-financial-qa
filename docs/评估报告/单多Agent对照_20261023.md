# 单 Agent vs 多 Agent 同任务集对照（2026-10-23）

## 结论

**[SKIP] 本轮未完成真实对照。**

原因有两层：

1. **环境阻塞**：Qdrant `localhost:6333` 超时、Docker daemon 未运行、API `localhost:8000` 无响应，无法对 A 类 22 题执行真实检索与生成。
2. **判定口径未冻结**：A 类 22 题里 12 题是原始观点/归因题，10 题是从 `anchor_cells` 反向生成的预测事实题；“任务成功率”尚未定义成可复现的二元判据（是命中金标值、引用正确研报，还是 claim faithfulness ≥ 阈值）。在口径未冻结前，跑出来的“成功率”不可比。

因此本报告**不提供**单/多 Agent 的新成功率、单位成功成本、协作 token 开销。

## 一、本轮原本要测什么

| 指标 | 定义 |
| --- | --- |
| 任务成功率 | 22 题中满足冻结判据的题数 / 22 |
| 单位成功成本 | 总 token / 成功题数 |
| 协作开销 | 多 Agent 的 supervisor + 子 Agent + aggregator token 总和，减去单 Agent 同题 token |
| 切换方式 | `AGENT_PLANNER_BACKEND=langgraph`，单 Agent `AGENT_LANGGRAPH_MULTI_AGENT=false`；多 Agent `=true` |

## 三、既有历史证据（不是本轮新结果）

以下数字来自既有报告，只用于说明对照方向，不能当作今天的新实验：

- `docs/评估报告/性能优化_并行缓存.md`：多 Agent 子任务串行 **107.9s** → 并行 **78.9s**，**-27%**。这是延迟收益，不是成功率收益。
- `docs/评估报告/MultiAgent对照.md`：多 Agent 复合题单题 109–155s，比自研单 Agent 纯财务题（约 23s）慢；当时结论是“多 Agent 适合归因/复合分析题，纯数据查询建议回退单 Agent”。
- 上述历史结果都不能回答“单/多 Agent 在 A 类 22 题上的成功率与单位成功成本”。

## 四、恢复条件

1. 启动 Docker Desktop / Qdrant，确认 `localhost:6333` 可达；
2. 启动 API 并确认 `/health` 返回 200；
3. 冻结 A 类 22 题的成功判据（建议：10 道预测事实题按金标值命中；12 道观点题按 claim faithfulness ≥ 0.8 且实体覆盖通过；两套判据分列，不混算）；
4. 用同一套题、同一模型、同一温度跑两组，记录每题 token 与成功标记；
5. 产出新报告，替换本 [SKIP] 状态。

## 五、边界

- 单 Agent 与多 Agent 的 token 统计必须包含 supervisor / aggregator 的调用；只统计子 Agent 会把协作开销低估。
- 失败题也要计入 token 分母；只对成功题求成本会美化单位成功成本。
- 本轮不把历史 107.9s → 78.9s 当成“多 Agent 成功率更高”的证据。
