## 一、「数字命中位置」上下文定位回退到全文首次出现（根因）

| 项 | 内容 |
| --- | --- |
| 现象 | 同一份研报的多个数字反复展示同一个「文件开头」片段；答案里被引用那句话所在的位置看不到 |
| 实测 | 10 条引用、`hits_context` 合计 **77 条**；多条上下文为同一段文件开头（如 `# 中药 Q3：业绩持续承压…投资要点：医药板块行情回顾…`） |
| 根因 | `src/pipelines/citation_validator.py::_extract_context`：优先用「引用片段内该数字 ±40 字符探针」在磁盘全文里定位；**探针失败即回退 `matches[0]`（全文第一次出现）** |
| 探针为何失败 | chunk 内容与磁盘全文存在差异——表格转文本、`[TABLE_PLACEHOLDER_N]` → `[表格数据详见研报原文，此处省略]` 替换、空白/换行归一化差异 |
| 影响 | 「数字命中位置」的**证据价值打折**：数字确实在原文里（数字核验 100% 通过），但展示的位置不是答案用到的那处 |
| 修复方向（未做） | 定位优先级改为 ① 引用片段所在 chunk 内定位 → ② 引用片段探针 → ③ 全文首次出现；UI 标注「位置：第 N 处命中」 |
| 风险 | 中——会改 `hits_context` 归档口径，需标注「不与旧归档直接对比」 |
| 面试口径 | 「这是已知边界：我定位到根因是探针失败后回退到全文首次出现，也写进了问题记录；面试前不动它，因为改定位会动归档口径。」 |

## 二、「数字命中位置」把日期与标题序号当关键数字（数字噪声）

| 项 | 内容 |
| --- | --- |
| 现象 | 列表里出现 `#3`、`#2025`、`#04`、`#27`、`#11` |
| 根因 | `CitationValidator.extract_numbers` 用 `\d+(?:\.\d+)?` 对引用片段**全量**抽数字，无「财务数值」判别；而引用片段是研报前 200 字，常为标题页（日期 / 评级 / 序号） |
| 影响 | 噪声数字占据列表，用户反而找不到真正的财务数值 |
| 修复方向（未做） | 方案 A：抽取时排除 4 位年份 / 纯月份日期 / 无单位无百分号的孤立短整数；方案 B：只对「答案正文里的数字」做归属核验（与「核验对象升级」同源） |
| 风险 | 中——改 `extract_numbers` 会动 L1 / golden 的抽取口径，历史回归数字需重跑并标注 |
| 面试口径 | 「抽数字的粒度我做了取舍：片段级抽取保证召回，代价是混入日期等噪声；要更准得把核验对象换成答案正文的数字，那是一次口径升级，我没在面试前动。」 |
