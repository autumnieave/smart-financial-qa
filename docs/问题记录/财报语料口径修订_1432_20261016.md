# 财报语料口径修订：1252 → 1432（2026-10-16）

## 结论

财报语料口径由「1252 份」修订为「**1432 份 = 1252 份正式 + 180 份测试**」。

## 依据（直连核验，2026-10-16）

| 项 | 事实 |
| --- | --- |
| 正式语料 | `data_corpus/全部数据/正式数据/附件2：财务报告` = **1252 份 PDF**（539 上交所 + 713 深交所） |
| 正式语料覆盖面 | 只覆盖 **70 家公司**（30 个 6 位代码 + 40 个公司名） |
| MySQL 现状 | `financial_database` 四表各 **903 行 / 80 家公司**（`core_performance_indicators_sheet` / `income_sheet` / `balance_sheet` / `cash_flow_sheet`） |
| 差的 10 家 | 凯莱英、迪安诊断、泰格医药、迈普医学、百普赛斯、百诚医药、昭衍新药、药明康德、成都先导、百克生物（CXO 板块） |
| 这 10 家的语料 | `测试数据/附件2：财务报告` = **180 份 PDF**（72 上交所 + 108 深交所） |

⇒ 单一 1252 份无法解释 MySQL 的 80 家公司；两份语料合并才是完整数据面。

## 抽取成功率口径（不报单一数）

`log_data_validation` 共 3519 行 = 3418 条 `SINGLE`（每份 PDF 一次校验尝试）+ 101 条 `ALL`（库级校验）；
表内**无文件名 / 公司 / 报告期字段**，且每行一个 uuid，3418 次尝试 ÷ 1252 份 = 2.7×（含历次重抽），
因此 **2664/3519 = 75.7% 是「校验尝试通过率」，不是文件级抽取成功率**。

文件级口径须用「文件名 ↔ 入库键」重建：

| 口径 | 派生键 | 命中 DB | 覆盖率 |
| --- | ---: | ---: | ---: |
| 仅正式语料（1252 份） | 772 | 733 | 94.9% |
| 正式 + 测试（1432 份） | 884 | 844 | 覆盖 DB 903 键的 93.5% |

残留未覆盖项主要为上交所 Q1（推导管径 artifact），非数据缺失。
文件级失败清单已归档（`TASKS/_archive/failed_files.txt`，快照 45 条），按原因可分为：
现金流量表三大现金流之和 ≠ 净现金流、利润表与核心表营业收入/净利润不一致、股票代码格式错误、
报告期格式错误、`Unknown column 'roe'` 插入失败、毛利率计算不一致、资产负债表不平衡、英文版无中文字段。
