# claim 结构行噪声过滤（2026-10-16）

## 背景

答案里的 markdown 标题会被抽成数字 claim：`### 1. 利润总额历史趋势分析` 的"命中数字"其实是
标题序号 `1`。产品层点开引用会显示成荒谬断言；评测层也会给每条引用凭空加一条噪声 claim。

## 修复

`src/tools/claim_evidence_locator.py` 新增 `is_structure_noise(text, numbers)` + 开关
`drop_structure_noise`（默认开，**评测层 `locate_answer` 与产品层 `locate_claims_per_reference` 共享**）：

1. 该行是结构行（`#{1,6}` 标题 / `1.` `1、` `(1)` `[1]` 序号；**不含** `-` `*` 列表符号）；
2. 该行数字**全部**是小整数序号（1 ~ `STRUCTURE_NOISE_MAX_ORDINAL`=12）。

保留：`1. 公司营收 12.3 亿元`、`### 2024 年营收 12.3 亿元`、`- 2 家公司净利润为负`。
`locate_answer` 的 meta 新增 `n_claims_dropped_structure`（不静默丢弃）。

## 实测（冻结池 `judge_input_108_agent_sql_20261015.json`，零 API 成本）

| 层 | before → after | 降幅 |
| --- | ---: | ---: |
| 评测层 claim 数（108 题） | 897 → 839 | 6.5%（20/108 题受影响） |
| 产品层 (引用, 断言) 对（59 题有引用） | 1189 → 934 | 21.4% |

## 口径影响

S5 工作单**尚未**按新规则重新生成，因此本次修复不改动已冻结口径；**下次重新生成工作单必须注明
「口径含结构行过滤」**，claim 数会比旧版少约 6.5%。
