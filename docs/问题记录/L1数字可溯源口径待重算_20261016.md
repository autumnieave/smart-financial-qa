## 一、现象

新的 claim 级证据定位器（`src/tools/claim_evidence_locator.py`）在真实材料上实测到两类**假阳性命中**，
根因都是「单位换算变体 + 纯子串匹配」过宽：

| 假阳性 | 触发链 | 说明 |
| :-- | :-- | :-- |
| `2120.99` 命中研报「PE(TTM): 21.21」 | `2120.99 万元 ÷100 = 21.21`，而 L1 的变体匹配是**纯子串** | 缩小方向变体在实务里几乎不成立 |
| `52.92` 命中 `5.29`（同类） | `52.92 ÷10 = 5.29` | 同上 |
| `12.3` 的 ÷10000 变体 `0`、`99.9` 的万元变体 `1` | 退化值（|值| < 1）在任意长文档里几乎必中 | 舍入到 `0`/`1`/`0.01` 的变体没有区分度 |
| 裸数字 `10`、`3`（来自「约10%」「Q3」） | 命中整库表格块里的 `2025H1: 10.04%`、`涨跌幅Q3: 14.90%` | 表格聚合块的"句子"里塞了几十个数字，句子级定位天然失效 |

## 二、影响面（为什么 L1 的对外数字可能被高估）

L1 对外口径目前是：

- 引用文本数字命中 **99.7%（9222/9248）**
- 端到端答案数字可溯源 **99.9%（4068/4071）**

这两项的复算脚本在历史上开启了 `accept_unit_variants=True`（单位换算变体视为命中）。
本次实测证明：**同一开关在退化变体与缩小方向上会产出假阳性**，因此上述两个数字存在**被高估的可能**，
在被同一套收紧规则重算之前，不应视作精确值。
